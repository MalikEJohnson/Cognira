Institutional memory

Your company remembers why, not just what.

Search tells you where a decision was written down. Cognira reconstructs the reasoning behind it — the options that lost, who argued for what, and the assumptions nobody checked.

01 / INGEST

Read what already exists

Folders, Slack and Gmail exports, Word documents, PDFs, mail archives, GitHub commits and pull request threads. Nothing has to be written twice.

02 / EXTRACT

Pull the reasoning out

Each document yields structured decisions: what was chosen, why, which alternatives lost and on what grounds, who was involved, and what was assumed without being verified.

03 / ASK

Reconstruct, don't retrieve

Ask why something happened and get an account assembled across every source, cited and scored — or a straight answer that the record does not say.

Why it is built this way

A memory that guesses is worse than none

Cognira is instructed to say when the record does not contain an answer, to attribute every claim to the document it came from, and to surface disagreement between sources rather than quietly pick one. An organisation acting on a confidently fabricated memory is the failure this is designed against.

Cognira makes a strong claim — that it reconstructs real reasoning instead of inventing plausible-sounding history. That claim is only worth anything if you can check it. Here is the code that actually runs, straight from the repository.

1 — What gets pulled out of a document

Extraction is not free-text summarisation. The model is held to a strict schema, so every decision comes back as validated data with the same shape every time. Note assumptions and evidence: the things a summary would throw away are exactly the things worth keeping.

3 — The call itself

                layer rather than parsed out of prose afterwards. If the model
                returns something that does not fit, it is rejected instead of

4 — Why follow-up questions are cheap

            

                Your whole corpus sits behind a cache breakpoint in the system
                prompt. The first question in a conversation pays for it; every
                follow-up reuses it at roughly a tenth of the input cost.

5 — How a payment is actually verified

            

                Nothing the browser says about a payment is trusted. The server
                reads the transaction back off chain and checks that the
                treasury's balance genuinely went up by at least the price. The
                transaction signature is a primary key in the database, so the
                same payment cannot be redeemed twice.
